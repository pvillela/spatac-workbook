The Spatac workbook is an Excel workbook used by the Antiquary condominium board for reserve fund project tracking and investment management. Examples are in the @_nogit directory.

The workbook has the following purposes:
1. Give us visibility to the details of the RFS in a form that allows us to perform analysis on it.  Prior to this, the board only got an RFS in PDF format.  I insisted that the vendor provide a spreadsheet without formulas (to protect their "secret sauce") back when we had the RFS done by Synergy and it has been a requirement for vendors since.
2. Validate the RFS study funding proposal to ensure the rate and planning horizon assumptions do not lead us to increase contribution rates more than necessary.
3. Track adjustments to project timing decided by Spatac.
4. Support investment planning.  I added this once our building had reached a critical age and it became clear that the prior policy, whereby Mike simply reinvested every maturity in a 5-year GIC, no longer met our needs.
5. Estimate the contribution increases that will be required after the next reserve fund study (RFS) to keep the fund balance above the required minimum.

I would like to accomplish the following goals with respect to the Spatac workbook:
- Make it more user-friendly. This is the overarching goal.
- Become familiar with @_nogit/Reserve_Fund_Investment_Policy-20261115-marked_up.docx.
- Become familiar with what an RFS looks like: @"_nogit/William11, RFS Update DRAFT4 (Run 7) October 30, 2024 (B&B).pdf".
- Restructure the workbook, as appropriate, to make it more modular and easier to maintain and use. In particular:
  - Everything needs to work both in the current version of Excel and LibreOffice Calc 26.2.
  - Clean-up unnecessary left-over garbage.
  - Remove the green highlighting (I think it's due to conditional formatting) of rows in the fvalues_spatac tab.
  - Use new-style array-valued formulas in lieu of repeatedly copied formulas where appropriate.
  - Use the `Index` function as needed to make it easier to shift or move data at the beginning of a new year or after a new RFS without breaking formulas.
  - Create range name tags to make the workbook and command line tools (described later) resilient to cell shifts.
  - Make clear what cells are open for user input and make them password-unprotected.
- The command line tools are to be written in Rust, using the `umya-spreadsheet` crate. The tools must work in both Linux and Windows.
- Licensing and GitHub build/release workflows should be analogous to what we did on the `ev-cost-recovery` project.
- Create a command line diff tool to compare two versions. The diff would be a Markdown file (unless you have a better suggestion) that identifies the following:
  - new tabs -- identify only
  - renamed tabs -- identify only
  - deleted tabs -- identify only
  - reordered tabs -- describe reordering
  - changed tabs -- describe structural changes and list individual cell changes (movement and content chages)
- It would be nice if the diff tool could be used with any workbook, not just the Spatac one -- but that is not a key requirement for this project.
- Create a command-line tool to extract the Medium_Term_Cashflow and Schedule_of_Investments tabs as a separate InvestmentPlan workbook. The references in those tabs to other tabs should be replaced with values. Portions of the two tabs that are not relevant to the investment plan should be removed in the resulting workbook.
- Create documentation explaining how to perform the functions described in the above list of purposes. Propose the most effective way to render the documentation. I lean towards Markdown but am open to other options that may be better.
